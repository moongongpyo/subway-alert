# URL to Playground

API 문서·공개 GitHub URL을 입력하면 Daytona에서 실행 환경을 준비하고 실제 기능과 Chromium 브라우저 동작을 검증한 후 체험 화면을 제공하는 로컬 MVP입니다. 같은 목적의 실험·피드백·대안 체험을 평가 프로젝트로 묶고 비교 리포트와 실행 레시피를 제공합니다. 기본 제품 기준은 [PLAN.md](PLAN.md), 확장 기준과 구현 대응표는 [EXPANSION_PLAN.md](EXPANSION_PLAN.md)입니다.

## 실행

Node.js **24 이상**이 필요합니다. Windows PowerShell에서는 `npm.cmd`를 사용하면 실행 정책 충돌을 피할 수 있습니다.

```powershell
npm.cmd ci
npx.cmd playwright install chromium  # 동적 문서 분석용 로컬 브라우저
# 기존 .env를 덮어쓰지 말고 필요한 값을 추가합니다.
# OPENAI_API_KEY=...
# DAYTONA_API_KEY=...
npm.cmd start
```

`http://127.0.0.1:3000`에서 열립니다. 기존 OpenAI 키가 설정돼 있다면 Daytona 키만 추가하면 됩니다. `.env` 변경 후 서버를 다시 시작하세요. 키를 UI·채팅·Git에 넣지 않습니다.

```powershell
npm.cmd run doctor  # 토큰 계측 / Daytona 읽기 / 공개 API 연결, 모델 생성 없음
npm.cmd run check
npm.cmd test
npm.cmd run test:docs-browser # 설치한 Chromium으로 문서 탭·iframe·요청 차단 검증
```

개발 중 자동 재시작은 `npm.cmd run dev`입니다. 준비 중 재시작하면 해당 작업은 중단하고 자원을 정리합니다. 호출을 자동 재생하지 않으며 이전 예산 원장은 보존됩니다.

Nosana 직접 배포 모델을 사용할 때는 [Nosana 연결·비용 제한·OpenAI 복구 안내](docs/nosana.md)를 참고하세요. 기존 에이전트 프롬프트는 공통으로 사용하며 `MODEL_PROVIDER`로 연결만 전환합니다.

화면 갱신은 SSE로 전달하며 작업 ID와 증가하는 이벤트 순번으로 복원합니다. 진행률은 **완료한 단계 수**이며 예상 시간이 아닙니다. 실패를 모의 성공 결과로 바꾸지 않습니다.

체험 제목은 입력 URL·확인한 서비스명·저장소명으로 자동 생성하며 첫 화면에서 이름을 묻지 않습니다. 같은 서비스를 다시 준비하면 `PokéAPI (2)`처럼 번호를 붙입니다. 최근 목록의 URL은 제목 아래 작은 글씨로 그대로 표시됩니다. 목록에서 상세를 열거나 이전 단계로 돌아간 뒤 제목 옆 `이름 변경`으로 수정할 수 있습니다. 이름은 실행 계약과 분리해 저장하며, 수정·새로고침·삭제 복원으로 번호나 실행 조건이 바뀌지 않고 모델도 호출하지 않습니다. 기존 기록에도 자동 제목을 적용합니다.

## 1단계 문서 탐색

- 여러 상품을 소개하는 문서에서는 확인된 링크로 선택 카드를 제공합니다. 선택 자체에는 모델을 호출하지 않고, 선택 후 같은 작업·예산 안에서 상세 문서를 분석합니다. SK의 정형 목록은 모델 없이 인식하며 일반적인 목록을 모델이 판별하는 경우에는 판별 호출 비용이 발생합니다. 대상 확정 전 샌드박스를 만들지 않습니다.
- 확인한 문서의 주소·제목·수집 방식과 탐색 경고를 준비 화면에서 볼 수 있습니다. 근거 부족은 `DOCUMENTATION_INCOMPLETE`로 구분하며, 실제 지원하지 않는 프로토콜 등의 `UNSUPPORTED`와 섞지 않습니다.
- API 주소는 본문뿐 아니라 문서 내 실제 호출 링크와 OpenAPI 명세에서도 확인합니다. 링크의 표시 문구에 호스트가 없거나 본문이 길어 잘려도 URL과 출처 페이지를 별도 보존해 최초 분석·수정 검증에 함께 전달합니다. 주소는 정확한 출처·호스트·프로토콜·포트로 비교하며 다른 도메인의 부분 문자열이나 전역 메뉴 링크만으로 승인하지 않습니다.
- 공식 호출 예제의 일반 링크를 브라우저로 여는 동작은 GET 메서드 근거로 전달합니다. 본문에 `GET`이라는 글자가 없다는 이유만으로 거절하지 않으며, 링크 근거와 실제 실행 성공은 구분합니다. 일반 탐색 링크·스크립트 실행 버튼은 이 근거로 취급하지 않습니다.
- `DOCUMENTATION_INCOMPLETE`에는 최대 2회의 분석 복구를 적용합니다. 1차는 이전 실패 이유와 수집 근거를 일반 분석 모델로 재검토하고, 2차는 원문 동적 본문·탭 및 실제로 발견한 관련 문서 최대 3개를 보완합니다. 보완 수집은 최대 4본문·24요청·60초이며 예제 API를 실행하지 않습니다. 새 근거가 없으면 추가 모델 호출 없이 종료합니다. 복구는 전체 수정 6회와 공통 요청·토큰·비용·시간 한도를 함께 차감하며, 이미 읽은 이미지는 다시 해석하지 않습니다. 복구 원인·조치·결과는 실행 내역에 남깁니다.
- 한 번의 수집: 본문 8개, 깊이 3, HTTP 요청 40회(브라우저 요청 포함), 12MB, 120초. 렌더링은 최대 2페이지·페이지당 문서 탭 5개, 이미지 읽기는 최대 2개·각 1MB입니다. 선택을 포함한 전체 작업은 24본문·160요청·선택 대기 3회 이내이며 기존 도구·모델·비용 제한도 함께 적용합니다.
- 브라우저는 새 세션에서 공개 자료만 읽습니다. 인증 정보·쿠키를 전송하지 않고, 모든 HTTP는 공용 IP 검사를 통과해야 하며 폼 실행·POST·WebSocket을 차단합니다. SK 문서 CMS의 공개 본문 조회 POST만 숫자 메뉴 ID를 받는 별도 어댑터로 처리합니다.
- 숨겨진 오류·서비스 종료 화면은 본문으로 선택하지 않으며 문서 탭의 숨겨진 내용은 유지합니다. 서울 열린데이터광장은 페이지에 명시된 데이터셋 ID와 `Open API` 탭 경로를 확인한 뒤 공개 명세를 GET으로 읽습니다. 인증키 신청 버튼의 실제 이동 주소는 사용자 안내에만 제공하며 자동 방문하지 않습니다. 전역 메뉴의 다른 데이터셋과 API 샘플 실행 링크는 문서 탐색에서 제외합니다.
- 문서 이미지 판독에도 토큰 계측·비용 예약을 적용하며 이미지 바이트는 작업 기록이나 후속 모델 컨텍스트에 저장하지 않습니다. 읽기 어려운 내용은 불확실성으로 남깁니다.
- 로그인·CAPTCHA 뒤의 문서, PDF 본문, 일반적인 사이트의 POST 기반 문서 조회는 자동 수집 대상이 아닙니다. 링크가 노출되지 않는 SPA나 비표준 탭은 추가 대응이 필요할 수 있습니다.

SK의 `svcSeq=60&menuSeq=125` 가이드는 최초 HTML 대신 별도 CMS 응답에 22개 상품 링크를 담습니다. 이 주소에서 선택 목록 수집과, TMAP 대중교통 상품의 외부 상세 문서에서 호출 URL·`appKey` 근거 수집을 실제로 확인했습니다. 인앱 브라우저에서 선택→8개 본문 수집→실제 모델 2회로 실행 계획 검증까지 통과했으며 수정 재시도는 없었습니다. 이후 기존 `apis.openapi.sk.com` 요금 상한 미등록 검사에서 중단됐습니다. 이 검증은 실제 API 호출·Daytona 준비 완료를 뜻하지 않습니다. 별도 Chromium 통합 테스트에서는 JavaScript 본문·iframe·탭 수집과 쓰기·내부망 요청 차단을 확인했습니다.

서울시 `OA-22718`은 데이터셋 소개·동적 Open API 명세·공통 이용안내 3개를 수집하고, 실제 모델로 `getNtceList`의 HTTP 8088·경로형 인증 계획을 검증해 사용자 키 연결 화면까지 확인했습니다. 별도로 공식 공개 `sample` 키 요청에서 정상 JSON 응답을 확인했습니다. 사용자 키 인증과 Daytona 전체 준비 완료는 이 검증에 포함되지 않습니다.

## 실험·대안·비교 확장

화면은 **링크 선택 → 체험 준비 → 목적·입력 → 실행 결과 → 다음 실험 → 비교 리포트**로 나누어 현재 단계에 필요한 기능만 표시합니다. 하단 공통 `이전` 버튼과 상단 단계 표시로 지난 단계를 읽기 전용으로 확인하고 현재 단계로 돌아올 수 있습니다. 실행된 입력·목적·결과는 기록을 그대로 보여주며, 조건 변경은 `조건을 바꿔 새 실험` 또는 실험 카드로 새 입력을 준비합니다. 단계 이동은 모델 호출·실제 실행을 일으키지 않고 작성 중인 폼과 파일 선택을 유지합니다. 원래 UI는 입력·실행 단계에서만 열며 과거 기록 화면에는 실행 가능한 iframe을 띄우지 않습니다.

- **내 용도로 확인하기**: 목적·기대 조건·선호를 버전별 저장합니다. 출력 필드의 존재·일치·문자열 포함 조건은 실제 응답으로 검사하고, 주관적 조건은 사용자 피드백으로 판정합니다. 실행 성공·목적 충족·만족 여부를 구분합니다.
- **맥락에 맞는 다음 실험**: 이전 입력·출력·피드백·검증한 조건과 문서 근거를 이용합니다. 카드에는 이유·변경점·확인할 조건을 표시합니다. 카드 선택은 입력을 준비하고 실제 실행은 별도 버튼으로 시작합니다.
- **대안 탐색과 재체험**: 공개 GitHub 검색과 README 최대 3개를 확인하거나 사용자가 입력한 API 공식 문서를 검토합니다. 정확한 출처 인용과 미검증 사항을 함께 표시합니다. 선택 시 별도 A–F 작업·샌드박스를 만들고, 이전 입력의 대응 여부와 새로운 전송 대상을 확인합니다. 키는 복사하지 않습니다.
- **누적 기록**: 목적·입력·결과·환경·변경점·피드백을 구조화해 보존합니다. 중복 요청은 재실행하지 않으며 처리 여부가 불확실한 요청은 미확정으로 남깁니다. 전체 대화와 파일 본문을 분석 모델에 전달하지 않습니다.
- **실행 레시피**: 검증 버전의 실제 성공 명령·설치 버전·파일·환경변수 이름·문제 해결 기록을 복사하거나 다운로드합니다. 비밀정보나 추정 명령은 포함하지 않습니다. 새 환경에서의 완전 재현을 보장하는 스크립트는 아닙니다.
- **비교 리포트**: 선택한 기록의 고정된 스냅샷으로 Markdown을 만듭니다. 선택적으로 모델 해석을 덧붙일 수 있습니다. 조건 차이·원본 결과·판정 근거·시간 측정 범위·미확인 비용·레시피를 표시하며 점수나 순위를 만들어내지 않습니다. PDF·Word는 아직 지원하지 않습니다.

원래 UI가 있는 저장소는 해당 UI를 그대로 사용하고, 실험의 입력 조건·출력·성공 여부를 사용자가 등록합니다. 자동 수집과 구분하며 실행 시간을 추정하지 않습니다. 자동 입력·출력 기록은 공통 폼을 사용하는 API·어댑터 체험에 적용됩니다.

기록은 30일, 파일은 기본 24시간 보관합니다. 사용자가 파일별로 생성 시점부터 7일까지 연장할 수 있습니다. 파일은 암호화해 별도 저장하며 1MB/파일, 프로젝트당 20개·총 20MB로 제한합니다. 리포트 다운로드는 최대 7일입니다. 샌드박스 만료와 기록 보관은 별도이고, 프로젝트 삭제 시 관련 파일·결과·리포트를 제거합니다. 정산된 내용 없는 비용 원장은 90일 후 정리하며 미확정 원장은 보존합니다.

프로젝트 전체 모델 상한은 $12이며 기존 사용자·서비스 일일 한도와 함께 적용합니다. 준비 작업은 최대 3개, 본 실험은 30회입니다. 추가 분석은 6회/$1 누적, 작업당 3회 호출/$0.20/120초입니다. 선택적 모델 리포트는 누적 $0.50, 작업당 2회 호출/$0.25/180초입니다. 목적·피드백 저장, 입력 편집, 기본 리포트·다운로드 자체는 모델을 호출하지 않습니다. 실행 후 결과 분석과 아래 사전 준비는 별도 계측 작업입니다. 이미지 카드를 선택하면 기존 이미지 생성 예산이 적용됩니다. 정책은 `src/evaluation-data.js`와 `src/evaluations.js`에 있습니다.

다음 실험 3개와 후속 질문은 기능 검증 후 브라우저 검증 중에 미리 준비합니다. 사용자가 카드를 골라 입력을 확인하는 동안 선택한 경로의 다음 한 단계도 준비하며, 실제 요청·이미지 생성은 미리 실행하지 않습니다. 목적·피드백·도구 버전·입력이 같은 요청은 저장한 캐시를 재사용합니다. 성공한 실행에만 미리 준비한 카드를 연결하고, 실제 결과 분석은 병행해 갱신합니다. 사전 제안에는 아직 받지 않은 결과의 성공·실패를 근거로 쓰지 않습니다. 오래된 조건의 카드는 다시 쓰지 않습니다.

사전 준비는 `gpt-5.6-luna` low를 사용하며 작업당 1회/$0.03/90초, 입력 8k·출력 3k, 프로젝트당 40회/$0.60 상한입니다. 같은 맥락에서 서로 다른 입력 경로는 최대 2개만 준비하며 새로고침·실패 시 자동 재시도하지 않습니다. 사전 준비와 결과 화면 생성을 분리해 병행하되 전체 모델 동시 2회와 프로젝트 $12 상한은 유지합니다. 추천 대기 문구는 표시하지 않고, 카드가 준비되면 보여줍니다. 캐시가 없거나 입력이 달라졌을 때의 생성 지연까지 없어지는 것은 아닙니다.

## 모델 및 강제 예산

기본 `gpt-5.6-terra` medium, 분류·인증은 `gpt-5.6-luna` low, 네 번째 수정 라운드에서만 `gpt-5.6-sol` medium입니다. CLI 내부 요청까지 호출 전에 예약하는 보장을 구현하기 어려워 PLAN 9.2의 대안인 **OpenAI Responses API + 직접 실행기**로 구현했습니다. 파일·셸·브라우저는 실제 Daytona에서 실행됩니다.

- SQLite `BEGIN IMMEDIATE` 안에서 작업·사용자·서비스 비용을 함께 예약합니다.
- 정확한 Responses 입력 토큰 계측 후 입력 + 출력 상한을 예약합니다. 토큰 계측 실패 시 생성하지 않습니다.
- 작업 48회 / 역할 16회 / 동시 2회, 입력 300k / 출력 80k, 요청당 20k / 4k, 작업 $3, 사용자 하루 $20 / 서비스 하루 $50, UTC 일자.
- 출력에는 추론 토큰을 포함합니다. 캐시 할인은 예상하지 않고 입력은 캐시 쓰기 최댓값인 기본 요율의 1.25배로 보수적으로 기록합니다. 표시 비용은 제공사 청구서와 동일한 정확한 금액이 아닙니다.
- SDK 자동 재시도는 0. 일시적 HTTP 오류는 추가 1회만 각각 예약 후 재전송합니다. 타임아웃·응답 유실은 미확정 비용 및 동시 요청 슬롯을 유지합니다.
- 도구 400회 / 브라우저 검증 7회·동작 600회 / 자동 API 호출 40회. 고정된 브라우저 실행기의 최대 동작 수를 먼저 예약합니다.
- 요율 검토 만료일 2026-11-21 이후 모델 호출을 차단합니다. `src/config.js`의 요율과 기한을 공식 문서 확인 후 갱신하세요.

## Daytona 실행 환경

작업마다 **1개 샌드박스**에 앱·DB·공통 UI·Chromium을 배치합니다. A–F는 역할이며 여섯 개의 상시 샌드박스가 아닙니다. 관리 키는 제어 서버에만 있습니다. 공개 저장소 코드는 로컬에서 실행하지 않습니다.

기본 Daytona 이미지에서 Node·Python·git, Playwright 1.58.2와 Chromium을 설치합니다. 개별 명령은 최대 120초이므로 첫 브라우저 설치가 오래 걸리거나 OS 패키지 권한이 부족하면 실패합니다. 브라우저 설치에만 파일 크기 한도 512MiB를 적용하고 일반 명령은 64MiB를 유지합니다. 브라우저 설치·실행기 오류나 프리뷰 연결 실패에는 모델 수정을 반복하지 않습니다. `sandbox/Dockerfile`로 사전 설치한 스냅샷을 준비할 수 있으며 Daytona에 등록한 이름을 `DAYTONA_SNAPSHOT`에 지정합니다. Dockerfile의 이미지 빌드·실제 Daytona 호환성은 별도 검증이 필요합니다.

리소스는 샌드박스 응답 기준 최대 2 CPU / 4 GiB RAM / 20 GiB 디스크로 검사합니다. 생성 시 TTL 120분, 완료 시 남은 TTL 60분을 설정합니다. 제어 서버 중단 시에도 Daytona TTL이 작동하도록 설정합니다. 모호한 생성 실패는 작업별 고유 이름으로 자원 정리를 재시도합니다.

해커톤 개발·시연용 기본값은 `DAYTONA_DAILY_MINUTES=10000`, `DAYTONA_MAX_SANDBOXES=10`입니다. 준비 30분·입력 대기 30분·체험 60분을 합쳐 작업당 120분을 일일 원장에 미리 예약하므로 Daytona 예약 기준 하루 최대 83회 준비·동시 최대 10개 환경을 허용합니다. 모델·프로젝트별 한도는 별도로 적용됩니다. 일찍 종료돼도 예약은 반환하지 않으며 UTC 자정(한국 시간 오전 9시)에 새 일자가 시작됩니다. 기존 원장은 보존하고 `.env` 변경은 서버 재시작 후 새 작업에 적용합니다. 이는 **자원·시간 한도이며 달러 요금 보장과 다릅니다.**

프리뷰는 비공개 샌드박스의 **포트 한정 서명 URL**만 사용자에게 전달합니다. 샌드박스 전체 접근이 가능한 표준 프리뷰 토큰은 서버 안에서만 사용합니다. 원본 UI의 iframe·쿠키·WebSocket 정책 또는 Daytona 안내 화면 때문에 임베드가 막히면 새 탭을 사용합니다.

Chromium은 자기 샌드박스의 `127.0.0.1` 서비스에 접속합니다. 샌드박스에서 공개 프리뷰를 거쳐 자기 자신으로 다시 접속하는 경로는 사용하지 않습니다. 공개 프리뷰 검사는 샌드박스 밖의 제어 서버에서 별도로 수행하며, 내부 브라우저만 통과하고 공개 접속이 실패하면 READY가 되지 않습니다. 확인 범위는 브라우저 증거 E와 공개 접속 증거 P로 구분합니다.

## 실제 지원 범위와 아직 검증하지 못한 부분

- 공개 CPU Node/Python 저장소, 단일 앱, SQLite/PostgreSQL, GET 또는 문서상 읽기 전용 POST API를 대상으로 구현했습니다. 프로젝트별 성공을 보장하지 않습니다.
- **사용자 API 연결:** A의 문서 분석 직후 C가 확인한 공식 키 발급 링크와 2~4단계 안내, 키 입력을 같은 화면에 제공합니다. 이미 키가 있으면 바로 입력합니다. 발급·로그인·상품 가입은 공식 사이트의 새 탭에서 사용자가 수행합니다. 키 연결 전에는 새 샌드박스나 외부 검증 호출을 시작하지 않습니다.
- **운영자 설정 없이 진행:** 미등록 API 호스트도 실패시키지 않고 사용자 연결 단계에서 기다립니다. 호출 조건은 이번 체험에만 적용하고, 기본 20회(3~50회) 안에서 자동 검증·재시도·브라우저 검증·사용자 실행을 합산합니다. 입력 대기 중에는 활성 준비 시간을 차감하지 않습니다.
- 요금 미확인 시 사용자가 과금 가능성을 확인하고 횟수 제한으로 진행할 수 있습니다. 이 모드는 **금액 상한을 보장하지 않으며**, 비용 기록·리포트에 미확인으로 남깁니다. 무료 잔여 한도 확인 또는 호출당 최대 USD·체험 예산 입력은 같은 화면의 선택 항목입니다. 무료 한도는 사용자 확인값이며 제공사 전체 계정 사용량을 조회하지 않습니다.
- FREE_API_HOSTS와 PAID_API_RATES는 선택적인 기본 요금 힌트입니다. 더 이상 등록을 필수로 요구하지 않으며 모델의 무료 주장은 그대로 승인하지 않습니다. 알려진 공개 무료 API는 기존처럼 바로 준비합니다. API 키·호출 조건은 다른 URL이나 인증 방식으로 자동 승계하지 않습니다.
- 401/403은 발급 안내와 키 재입력을 요청하며 모델 수정 호출 없이 재개합니다. 키 교체·단계 이동·환경 재설치로 기존 호출 사용량을 초기화하지 않습니다. 종료·입력 대기 상태에서는 진행 막대를 움직이지 않습니다. 이전 요금 설정 오류 기록에는 새 연결 흐름으로 시작하는 안내를 제공합니다.
- API 키는 암호화된 제어 서버 저장소에서 인증 시 필요한 작업 런타임으로만 전달됩니다. 런타임은 대상 origin을 고정하고 DNS·리다이렉트·응답 크기를 검사합니다. 범용 프록시 또는 키 발급 자동화는 제공하지 않습니다.
- HTTP·HTTPS의 공개 API와 명시적 포트(예: 서울시 `:8088`)를 지원합니다. 경로형 인증은 `/{apiKey}/` 템플릿에 사용자 키를 실행 직전에 인코딩해 삽입하며 일반 입력·계획·로그에는 키를 넣지 않습니다. HTTP로 키를 전달할 때에는 연결 화면에서 **평문 전송을 별도로 확인**해야 하고 런타임도 같은 확인을 검사합니다. 문서에 없는 HTTPS 주소로 자동 변경하지 않습니다. 내부망·메타데이터 주소·URL 사용자명/비밀번호는 계속 차단하며 인증 요청의 리다이렉트는 허용하지 않습니다.
- **외부 키가 필요한 원본 저장소는 현재 차단**합니다. 임의 저장소의 인증키 연결·호출 수·요금을 집행하는 경로는 별도 구현이 필요합니다.
- MVP는 API·저장소 모두 **Daytona 계정의 기본 네트워크 정책**을 사용합니다. 생성·설치·수정 재시도·실행 후에 작업별 `domainAllowList`, `networkAllowList`, `networkBlockAll`을 설정하지 않으며, 작업별 허용 목록 지원 여부로 저장소 실행을 차단하지 않습니다. Tier 1·2의 조직 제한은 그대로 적용되고 Tier 3·4에서는 기본 외부 인터넷 접속을 사용할 수 있습니다. 업그레이드 후 새 체험을 시작하면 이 정책으로 환경을 생성합니다.
- API 작업은 샌드박스 생성 직후 공개 IP 검사와 8초 연결 점검(HTTP: TCP, HTTPS: TLS 호스트·인증서 확인)을 먼저 수행합니다. 이 점검에는 인증키나 HTTP 요청을 보내지 않습니다. 연결 불가 시 UI 생성·패키지 설치 이전에 중단합니다. 이후 실제 호출에서 발생한 네트워크 시간 초과도 `EXTERNAL_UNREACHABLE`로 구분해 모델 수정으로 반복하지 않으며, 브라우저 검증까지 같은 원인을 보존합니다. 연결 성공은 API 기능·인증 성공을 의미하지 않습니다.
- 서울시 `getNtceList`는 로컬 공개 샘플 호출에서는 정상 응답했지만, 확인 당시 Tier 1 Daytona 환경에서는 `openapi.seoul.go.kr:8088` TCP 연결부터 시간 초과했습니다. 같은 환경에서 GitHub 연결은 성공했습니다. [Daytona 네트워크 정책](https://www.daytona.io/docs/en/network-limits/)과 계정 Limits의 Internet Access 권한을 확인해야 하며, 이 상태를 API 기능 미지원이나 인증키 오류로 판정하지 않습니다.
- 기본 실행은 **loopback 단일 사용자 앱**입니다. Railway 배포는 HTTPS와 HTTP Basic 인증으로 보호하는 **단일 운영자 공간**이며, 로그인 정보를 공유하면 모든 기록과 실행 권한도 공유됩니다. 다중 사용자 서비스에는 사용자별 소유권, 별도 키 관리와 작업 큐가 추가로 필요합니다.

## Railway 단일 운영자 배포

- 루트 `Dockerfile`은 Node 24, 앱 의존성과 문서 분석용 Chromium을 설치합니다. 로컬 `.env`, 데이터, 키와 로그는 이미지·업로드에서 제외합니다.
- 서비스 시작 명령은 `node src/server.js`, 헬스체크는 `/healthz`, 인스턴스는 1개입니다. `/app/data`에 영구 볼륨을 연결해야 SQLite 기록·암호화 키·결과 파일이 재배포 후에도 유지됩니다.
- `HOST=0.0.0.0`, `PUBLIC_ORIGIN=https://<서비스 도메인>`, `ACCESS_USERNAME=admin`, 무작위 `ACCESS_PASSWORD`(24자 이상)를 설정합니다. 외부 모드는 유효한 HTTPS 주소와 비밀번호가 없으면 시작하지 않습니다.
- `OPENAI_API_KEY`, `DAYTONA_API_KEY`는 Railway 변수로 설정합니다. 기존 지하철 DB는 현재 앱에서 사용하지 않습니다.
- `/healthz`만 인증 없이 응답하며 화면·API·다운로드에는 로그인이 필요합니다. Railway TLS 프록시 뒤에서 운영하며 직접 HTTP 접속은 허용하지 않습니다.

2026-09-19 수정 후 검증: 문법 검사와 자동 테스트 **78개 통과**. 목적 저장 중 입력 유지, 편집한 입력을 반영한 실험 제안, 카드 선택 시 입력만 준비, 중복·실행 중 요청의 재실행 방지, JSON 객체의 순서와 무관한 동등 비교, 취소 이후 반환된 환경의 정리를 검증했습니다. 내부 브라우저 성공만으로 READY가 되지 않는 전체 제어 흐름도 테스트합니다. 인앱 브라우저의 분리된 fixture에서 목적 저장 → 실행 → 후속 카드 준비 → 두 번째 실행 → 비교 리포트 생성을 다시 확인했습니다. fixture는 실제 외부 실행으로 표시하지 않으며 제품 서버에 노출되지 않습니다.

수정 전 실제 연결 검증에서는 OpenAI 토큰 계측·Daytona 읽기·공개 API 수신, Daytona 생성·Chromium 설치·GitHub API 기능 검증까지 성공했습니다. 당시 샌드박스→서명 프리뷰 접속이 `ERR_CONNECTION_RESET`으로 실패한 원인을 위 검증 경로 분리로 수정했습니다. **수정된 전체 READY 경로의 원격 재검증은 아직 남아 있습니다.** 당시 300분 한도로 막혔던 준비 횟수는 해커톤 개발·시연을 위해 10,000분으로 상향했습니다. 한도 부족은 A 모델 호출 전에 차단합니다. DB·원본 UI 저장소의 원격 실행도 별도 검증이 필요합니다.
